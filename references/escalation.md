# 分级检测路由：从零接入到数据源核验

本文件定义 Step 0 探测到凭据后，维度 A（知识产权风险）如何从「文本模式匹配」升级到「数据源核验」。
其余三个维度（B 广告违规、C 平台政策、D 跨境法规）纯靠规则库，不受本文件影响。

**总原则：有凭据不等于全打。** 按维度 A 扫出的线索分诊，只调真正对题的那一两路。无差别全扫既贵又会把噪声灌进报告。

---

## 一、为什么要这一层

零接入路径下，维度 A 靠的是品牌词表和表述模式匹配。它能抓住「标题里写了 Nike」这类**文字**问题，抓不住**形状和图案**问题：

| 风险面 | 零接入能做什么 | 实际缺口 |
|--------|---------------|---------|
| 文字商标 | 匹配已知品牌词表 + 公开库检索 | 词表外的在册商标、跨语种近似 |
| 图形商标 / logo | 靠模型看图描述 | 无相似度比对，近似图形标漏检 |
| 外观专利 | 无 | **完全盖不住**，这是 TRO 的主要来源 |
| 版权形象 | 能认出知名 IP 角色 | 认不出非知名的已登记作品 |
| 实用新型 / 发明 | Google Patents 关键词 | 不知道该查哪个专利时就查不到 |
| 禁售品视觉识别 | 靠品类清单 | 形态上违规但描述正常的漏检 |

**下架和 TRO 大多来自图像侵权，而图像侵权恰好是零接入盖不住的那一半。** 这就是这层存在的理由。

## 二、分诊表：什么线索升级到哪条通道

维度 A 扫完后，按下表决定是否升级。左列命中才调对应通道。

| 维度 A 的线索 | 升级到 | 首选通道 | 备选 |
|--------------|--------|---------|------|
| 有产品图，且造型/外观本身是卖点 | 外观专利图搜 | TroHub `designPatent`（¥0.14） | 睿观 `detectionPatentDesign`（¥0.61–0.92） |
| 图上有图形标、图案、装饰性 logo | 图形商标图搜 | TroHub `trademark`（¥0.14） | 睿观 `trademarkGraphicDetection`（¥0.61–0.92） |
| 图上有卡通形象、插画、角色、摄影作品 | 版权图搜 | TroHub `copyright`（¥0.70） | 睿观 `copyrightDetection`（¥0.31–0.61） |
| 产品有机械结构、功能创新、独特机构 | 实用新型/发明检测 | **只有睿观** `utilityPatentDetection`（¥0.92） | 无 |
| 品类涉管制品、武器配件、形态敏感 | 图片政策合规 | **只有睿观** `gunPartsSearch`（¥0.31） | 无 |
| 品牌词、标题里的疑似商标词 | 文字商标核验 | TroHub 文字商标（¥0.06） | 睿观 `textTrademarkDetection`（¥0.31）／卖家精灵 `trademark_*` |
| 上面任一路命中了专利号 | 专利深核 | 智慧芽直连 MCP（不耗积分） | LinkFox 版智慧芽（¥0.03/次） |

同款能力 TroHub 单价明显更低，所以它是默认主力；睿观的不可替代价值在**实用新型检测**和**图片政策合规**这两路。

## 三、各通道调用方式

### TroHub（凭据 `TROHUB_API_KEY`）

客户端按 trohub-ip-check 自身的约定读取凭据，通常不需要手动 export。

```bash
python3 <trohub-ip-check skill 目录>/scripts/trohub_client.py check-image \
  --image <公网图片URL> --sources designPatent trademark copyright \
  --product-name "<产品名>"
```

- 图像检测是**异步**的：提交成功不等于检测完成，必须轮询到终态才算数。
- 限流：图像 10 次/分，商标与专利反查 30 次/分，并发 ≤3。
- 三个 source 可以只挑需要的；全扫 35 积分，单扫外观或图形商标各 5 积分。
- 付费查询前先跑一次固定测试集对漂移台账（见第四节）。

### 睿观（凭据 `LINKFOX_AGENT_API_KEY`，网关 `${LINKFOX_TOOL_GATEWAY}`）

统一走 LinkFox 厂商 skill 自带的脚本。厂商 skill 装在哪里，就用 `LINKFOX_SKILLS_DIR` 指向那个目录：

```bash
python3 "<LINKFOX_SKILLS_DIR>/linkfox-ruiguan-<名称>/scripts/ruiguan_<名称>.py" '<JSON参数>'
```

| 路 | 端点 | 必填参数 | 单价 |
|----|------|---------|------|
| 实用新型/发明检测 | `POST /ruiguan/utilityPatentDetection` | productTitle、productDescription、region、topNumber | ¥0.92 |
| 图片政策合规 | `POST /ruiguan/gunPartsSearch` | imageUrl | ¥0.31 |
| 外观专利检测 | `POST /ruiguan/detectionPatentDesign` | imageUrl、topNumber | ¥0.61 / 0.92 |
| 图形商标检测 | `POST /ruiguan/trademarkGraphicDetection` | imageUrl、topNumber | ¥0.61 / 0.92 |
| 版权检测 | `POST /ruiguan/copyrightDetection` | imageUrl、topNumber | ¥0.31 / 0.61 |
| 文字商标检测 | `POST /ruiguan/textTrademarkDetection` | productTitle、region | ¥0.31 |

要点：

- **实用新型和文字商标是文本输入**，不需要图片 URL；其余四路要**公网可访问的图片 URL**，本地文件先传到可公开访问的位置。
- 斜杠两档价是「雷达检测」开关，开了更贵；官方没说明雷达多做了什么，未实测前按低档估算、按高档预留。
- `topNumber` 固定计费，不随条数变，所以要么别调、要么直接给 100。
- 响应里的 `costToken` 实测可能为空，**实际扣点只能去 LinkFox 控制台的「算力点消耗明细」看**。

### 智慧芽（直连 MCP，会话里有 `mcp__zhihuiya-patent__*` 才可用）

只在上游命中专利号之后才调。查法律状态、权利要求、同族、是否已失效或被无效。直连不消耗 LinkFox 积分。

### 卖家精灵（直连 MCP，`mcp__sellersprite-mcp__trademark_*`）

在册文字商标兜底，走已购配额。

## 四、纪律（付费通道必须遵守）

1. **开跑前确认余额。** LinkFox 积分归零时**不会明确报错**：新任务报 `errcode=501`，在跑的任务里付费技能逐个报 402，而 agent 会自行换源或跳过，**交回来的报告看着完整其实缺数据**。落在合规上就是一份「没查到风险」的假阴性。每批开跑前先确认，跑完核对返回字段是否齐全，缺字段一律当失败处理，不得当作「没风险」。
2. **先对漂移台账。** TroHub 服务端返回结构变动频繁且不通知。批量付费查询前，先用一组**固定测试集**（输入固定、预期结构已知）跑一遍冒烟，对照你自己维护的漂移台账；对不上先查接口有没有变，再查产品。没有台账就先建一个——这是付费数据源的必需品，不是可选项。
3. **原始返回必须落盘。** 每次付费查询的请求参数与完整响应都要存档，报告里的每条结论要能回溯到具体那次查询。合规结论是拿去对供应商、对平台、对律师的，不能只留一句「查过了没问题」。
4. **调用前说明消耗。** 同一会话同一参数默认只调一次。失败或空结果不得自动换关键词、翻页、改参数连续试探；需要再查先跟用户说会产生额外消耗。
5. **绝不打印凭据。** 不 echo、不写进报告、不入日志，连首尾几位都不打。排障时用 `detect_capabilities.py` 确认「存在与否」即可。

## 五、结果判读：相似度不是结论

数据源返回的是**候选清单**，不是判决。实测过的典型情况：一次实用新型检测返回 100 条、56 条标记有效，但真正对题的只有 1 条——其余是词面相近的无关品类（查「家禽轮椅」返回一堆养殖场运鸡设备）。

所以：

- **不要把「有效条数」当风险数量**写进报告，那个数字没有决策价值。
- 按相似度排序只用来决定**先看哪条**，不用来定性。
- 对每条高相似度且有效的结果，回到**独立权利要求逐要素比对**：少一个要素就不落入该权利要求。
- `troCase` / `troHolder` 为真的结果优先看，它意味着这个权利人真的在打官司。
- 判定写成「落入 / 不落入 / 需律师确认」，并写明依据的是哪一条权利要求的哪个要素。

## 六、报告里的覆盖声明（必填）

无论走哪条路径，报告都必须有一段说明本次**实际查了什么、没查什么**：

- 零接入：写明「本次未做图像相似度比对，外观专利与图形商标未覆盖；结论仅基于文案与公开检索」。
- 数据源增强：逐条列出调用了哪些通道、各自查了什么、命中多少条、花了多少。
- 两种路径都要带这句：**查不到不等于安全**——在审未公开的专利、刚受理的商标、未入库的版权登记，任何一档都看不见。

隐去覆盖范围的合规报告比没有报告更危险，因为它会被当成安全证明。
